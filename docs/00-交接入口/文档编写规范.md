# 文档编写规范

1. **目录约定**（项目级 `AGENTS.md` / `CLAUDE.md` 或用户直接指令另有更严格约定的，从其约定）：
   - 交接入口统一在 `docs\00-交接入口`：`项目概览.md`、`迭代路线图.md`、`当前状态与待办.md`、`文档编写规范.md`。
   - 历史与后续工作统一在 `docs\01-迭代记录\YYYY-MM-DD-迭代名称`，每个迭代必须含 `迭代总览.md`。
2. **状态取值**：`计划中`、`进行中`、`已完成`、`已取消`，不得使用其他状态。
3. **同步维护**：新增 / 移动 / 更新迭代资料后必须同步 `迭代路线图.md`；进行中事项或交接风险变化时必须更新 `当前状态与待办.md` 并刷新其 `更新时间：YYYY-MM-DD HH:mm（Asia/Shanghai）`。
4. **归档位置**：设计方案、实施计划、执行报告、验收结果和审阅资料一律放所属迭代目录，不使用平行文档目录。
5. **命名**：文件名使用简体中文和用途名称，禁止 `task-1`、`review-package` 等内部命名。
6. **Git**：需要供团队交接的文档默认提交到 Git；提交前检查 `.gitignore` 确认不会因忽略规则丢失。
7. **语言**：全部文档正文使用简体中文；代码标识符、命令、专有名词保留英文。
