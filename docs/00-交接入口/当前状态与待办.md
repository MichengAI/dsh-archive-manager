## 交接风险

- **CI 自动发布从未成功过（遗留问题，非阻塞）**：本次 0.1.11 由维护者本地凭证手工发布。CI 的 `npm publish` 返回 E404 根因：npm 侧未配置 Trusted Publisher（OIDC），workflow 也没有 `NODE_AUTH_TOKEN`；npm 对无权限的 PUT 返回 404（以 404 掩盖 403）。历史显示 `[ok]` 的发布 run 均为版本已存在的 skip。如需打通 CI 发布，二选一：
  1. **Trusted Publisher（推荐，无凭证）**：npmjs.com 包设置中添加--repository `MichengAI/dsh-archive-manager`、workflow `publish.yml`、environment 留空、ref `refs/tags/v*`；
  2. **传统 token**：GitHub Secrets 添加 granular `NPM_TOKEN`（仅该包 publish 权限），workflow publish 步骤加 `env: NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`。
- **测试依赖宿主环境**：`test/node_modules` 是指向 `%USERPROFILE%\.dsh\profiles\node_modules` 的 junction，本机外（CI）需自备同版本 `@deepseek-ai/*` 依赖。
