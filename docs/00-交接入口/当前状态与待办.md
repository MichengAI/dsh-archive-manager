## 交接风险

- **npm 发布凭证缺失（当前最高优先级）**：两条可行路径任选其一——
  1. **Trusted Publisher（推荐，无凭证）**：npm 管理员在 npmjs.com 的 `@michengai/dsh-archive-manager` 包设置中添加 Trusted Publisher：repository `MichengAI/dsh-archive-manager`、workflow `publish.yml`、environment 留空、ref `refs/tags/v*`；配置后重跑失败的 run 或重推 tag 即可。
  2. **传统 token**：在 GitHub 仓库 Secrets 添加具备发布权限的 `NPM_TOKEN`（granular token，仅该包 publish 权限），并在 publish 步骤加 `env: NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`。
  - 注意 npm 对绕过 2FA 的 legacy token 有收紧限制，granular token 需允许 CI 发布。
- **测试依赖宿主环境**：`test/node_modules` 是指向 `%USERPROFILE%\.dsh\profiles\node_modules` 的 junction，本机外（CI）需自备同版本 `@deepseek-ai/*` 依赖。
